# Non-blocking Chinese disambiguation

## Objective

Keep the current chin disambiguation worker calls and their classification behavior, but remove them from the user-facing subSeg save critical path.

After a save:

```text
user save -> persist subSeg/langUnits -> respond immediately -> queue disam -> worker -> guarded langUnit update -> quiet client refresh
```

The user must be able to continue typing, navigating, and saving while disambiguation runs. Disambiguation work must execute in order and must never overwrite a newer user save.

## Current blocking seam

- `src/main.js:saveSubSeg()` sends `disambiguateChinContexts` with the save payload.
- `src/public/server.js:POST /api/subSegs/items` writes the save, rebuilds langUnits, then awaits `maybeDisambiguateLangUnitContexts()`.
- `maybeDisambiguateLangUnitContexts()` loops instances sequentially and awaits `inferLangUnitChineseTypes()` for each worker call.
- `inferLangUnitChineseTypes()` calls the long-lived worker with `task: "contextType"`, then reads and rewrites `langUnits/items.json`.
- The POST response is withheld until every candidate has finished and a second rebuild has completed.

## Target contract

The POST response returns after the ordinary save path, with a small queue acknowledgement:

```json
{
  "subSeg": {},
  "subSegs": [],
  "langUnits": [],
  "chinDisambiguation": {
    "queued": 2,
    "queueId": "..."
  }
}
```

`langUnits` in this response is the immediate post-save state. Later worker results are observable through the normal `GET /api/langUnits/items` refresh; no worker result is required in the original save response.

## Vertical tracer bullet

### Phase 0 — characterize the existing save path

Trace one ambiguous Chinese bubble from save through response and reload.

- [ ] Record the current request/response timing for zero, one, and multiple candidates.
- [ ] Confirm candidate identity fields: `langUnitId`, `audSegId`, `subSegId`, `cycleGroupId`, `start`, `end`, context text, and target text.
- [ ] Confirm normal save still preserves subSeg newlines and `<br>` rendering.
- [ ] Gate: a baseline save fixture and one manual browser path are available before changing timing.

### Phase 1 — extract a durable, stale-safe disam job

Add the smallest job shape in `src/public/server.js`; do not enqueue whole mutable langUnit objects.

```js
{
  jobId,
  langUnitId,
  instance: { audSegId, subSegId, cycleGroupId, start, end },
  context,
  target,
  substring,
  enqueuedAt
}
```

- [ ] Extract candidate jobs from the post-save `updatedLangUnits` result.
- [ ] Keep the captured context/target text and the instance locator in the job.
- [ ] Add an in-memory FIFO queue and one drain promise/lock; only the drain may call the disambiguation worker.
- [ ] Ensure duplicate jobs for the same save are not added twice.
- [ ] Keep the existing worker request payload unchanged: `task`, `context`, `target`, `substring`, and `instance`.
- [ ] Gate: enqueueing is synchronous and returns a queue count without starting a second concurrent worker request.

### Phase 2 — move the response boundary

Change only the POST ordering first.

- [ ] Persist the subSeg and supplied langUnits exactly as today.
- [ ] Run the ordinary `rebuildLangUnitItems()` and linked-subSeg hydration exactly as today.
- [ ] Replace the awaited `maybeDisambiguateLangUnitContexts()` call with candidate extraction plus queueing.
- [ ] Send the existing response immediately, adding only queue metadata.
- [ ] Start/continue the queue drain after the response has been sent; never make the request handler await it.
- [ ] Keep root inference behavior separate; this change is only for `task: "contextType"`.
- [ ] Gate: browser save latency no longer includes worker latency, while the worker still receives the same candidate payloads in the same order.

### Phase 3 — make result application guarded and sequential

Reuse `inferLangUnitChineseTypes()` only after making its write target safe for background work.

- [ ] For each job, call the worker once, then reread current `langUnits/items.json`.
- [ ] Locate the exact current instance by the saved instance locator.
- [ ] Apply the result only if current context text/type inputs and target text still match the job snapshot.
- [ ] If the instance was edited, deleted, rebound, or canonicalized since enqueue, mark the job stale and skip it quietly.
- [ ] Write one result, then rebuild/sync dependent langUnits before draining the next job.
- [ ] Keep the queue FIFO and await each job before starting the next one.
- [ ] On worker or write failure, record failure status, continue with the next job, and avoid rejecting the already-sent save.
- [ ] Gate: two queued jobs update in order; a newer save cannot be reverted by an older worker result.

### Phase 4 — quiet client convergence

Use the existing `GET /api/langUnits/items` path rather than adding push infrastructure.

- [ ] Add a lightweight server status endpoint or extend the existing worker status response with queue counts and a monotonic `changedAt`/revision.
- [ ] After a save with queued jobs, start one debounced background refresh loop in `src/main.js`.
- [ ] Poll only while this page has pending disam work; stop when the queue is empty or after a bounded idle period.
- [ ] Merge refreshed langUnits into in-memory state without rerendering the active subSeg editor.
- [ ] Re-render only affected langUnit bubbles/derived displays; preserve focus, caret, draft text, and newline behavior.
- [ ] Do not show a blocking modal or toast for ordinary queue progress; worker failures may use the existing quiet worker toast only if diagnosis is needed.
- [ ] Gate: while typing in a subSeg, background completion updates classifications without stealing focus or changing editor text.

### Phase 5 — verification slice

- [ ] Unit/self-check: FIFO drain permits one worker request at a time.
- [ ] Unit/self-check: stale snapshot is skipped after a newer instance save.
- [ ] Unit/self-check: worker failure does not block later jobs.
- [ ] Integration check: POST returns before a deliberately delayed worker response.
- [ ] Integration check: eventual langUnit type changes are persisted and visible after refresh/reload.
- [ ] Browser check: save an ambiguous target, immediately type another line, and confirm no input pause.
- [ ] Browser check: save several ambiguous instances and confirm results arrive in queue order.
- [ ] Browser check: edit/delete an instance while its old job is pending; confirm the old result does not reappear.
- [ ] Browser check: verify subSeg newline, `<br>`, IME Enter, bubble targeting, and linked child rows remain unchanged.

## Suggested minimal implementation surface

- `src/public/server.js`
  - Add queue state and a FIFO drain beside the existing worker client.
  - Extract candidate jobs from the current `maybeDisambiguateLangUnitContexts()` loop.
  - Split “classify one job” from “await all jobs”.
  - Return queue metadata from `POST /api/subSegs/items`.
  - Expose queue status/revision for client convergence.
- `src/main.js`
  - Treat the save response as immediate state.
  - Start one debounced background langUnit refresh when queue metadata is present.
  - Merge results without replacing the active editor DOM.
- `mgmt/codex-worker/src/*`
  - No behavior change expected; retain the existing `contextType` task and serialized request client.

## Deliberate simplifications

- One process-local FIFO queue is sufficient for this single dev server; add durable jobs only if work must survive process restarts.
- Polling the existing collection endpoint is sufficient; add SSE/WebSocket push only if refresh latency becomes visibly unacceptable.
- Do not parallelize worker calls: sequence is required for predictable file writes and worker session use.
- Do not change classification heuristics, candidate filters, schemas, or subSeg content shape in this refactor.

## Done when

The first save response is independent of worker duration, queued disambiguation still applies the same classifications in order, stale jobs cannot overwrite newer data, and the active subSeg editor remains uninterrupted through background completion.
