# Composite Cycle-Target Capture Refactor

## Objective

Refactor non-contiguous capture while a cycle-targeted langUnit is active so the selected addition reprocesses that occurrence into a new or recalled composite canonical langUnit rather than creating the addition as an independent canonical langUnit.

Example:

```text
这个消息又被进一步升级了
```

Selecting `被` while `消息` is cycle-targeted must preserve `消息` as the canonical seed, record `被` as an addition, classify the aggregate as `chinColl`, and keep unrelated `消息` occurrences unchanged.

## Guardrails

- Keep canonical langUnit identity global and reusable; never globally reclassify the original item because one occurrence became composite.
- Treat reprocessing as an occurrence rebind: remove the old `(langUnitId, instance)` binding, then perform new/recall against the aggregate `(text, target.type)` identity.
- Store composite provenance on the resulting aggregate langUnit item, with a composition ID for the part structure and occurrence binding.
- Preserve each part's source text, source langUnit ID, offsets, provenance role, and original target type.
- Keep ordinary single-bubble capture and contiguous capture behavior unchanged.
- Keep current newline and `<br>` handling intact in every subSeg editor path.
- Do not use `text` fields on persisted `langUnitRef` tokens as the source of truth; resolve display text from the referenced part or canonical item.
- Make server rebuild idempotent: repeated saves must not duplicate parts, instances, or compositions.
- Treat legacy refs without composition metadata as ordinary canonical refs.
- The seed is preserved as provenance, but this occurrence is not preserved as an instance of the seed after successful reprocessing; it is rebound to the aggregate item's canonical identity.

## Vertical Tracer Design

Each phase traces one complete slice through:

```text
user action -> DOM state -> extracted payload -> API -> persisted data -> rebuild -> rendered state
```

No phase is complete until its tracer path works in a live browser and survives a reload.

## Phase 1: Schema and Identity Primitives

> Trace: one composite record can be represented without changing runtime behavior.

- [ ] Extend the langUnit schema with `compositions` on the resulting aggregate canonical item. A composition is provenance for one aggregate item, not a replacement for canonical identity.
- [ ] Define the minimum composite shape:
  - `compositionId`;
  - `seedLangUnitId`;
  - `scope.audSegId`;
  - `scope.subSegId`;
  - `scope.cycleGroupId`;
  - aggregate `text`;
  - aggregate `target`;
  - ordered `parts`.
- [ ] Define each part shape:
  - `partId`;
  - `sourceLangUnitId` or `null` for a new addition;
  - `text`;
  - `role: seed | addition`;
  - `start` and `end`;
  - original `target.text` and `target.type`.
- [ ] Extend subSeg `langUnitRef` tokens with optional:
  - `compositionId`;
  - `partId`.
- [ ] Extend non-root subSeg linkage with optional `linkTargetCompositionId`.
- [ ] Add `chinColl` and `engColl` to target-type normalization and schema enums.
- [ ] Implement pure identity helpers:
  - canonical recall/new key from normalized aggregate `text` plus `target.type`;
  - old-binding removal key `(sourceLangUnitId, audSegId, subSegId, instance span)`;
  - composition scope key;
  - deterministic part key;
  - aggregate canonical lookup/create;
  - composition lookup on the resulting aggregate item;
  - legacy fallback to ordinary langUnit behavior.
- [ ] Keep the original seed item's canonical text/type and unrelated instances unchanged; only the matched occurrence is removed from its `instances`.
- [ ] Do not change rendering, capture, or save behavior yet.
- [ ] Gate: schema fixtures round-trip through normalization with no data loss, and legacy data serializes byte-equivalently except for permitted normalization.

## Phase 2: Read-Side Resolution and Rendering

> Trace: persisted composite data renders correctly before new composite data can be created.

- [ ] Update langUnit text resolution to understand `compositionId` and `partId`.
- [ ] Update `renderSubSegContentTokens` so each ref renders its own part text, not aggregate composite text.
- [ ] Update bubble attributes to carry:
  - canonical `data-langunit-id`;
  - `data-langunit-composition-id` when present;
  - `data-langunit-part-id` when present;
  - effective cycle group identity.
- [ ] Update group collection, targeted styling, connectors, and reference lists to group by effective target key.
- [ ] Update cycle child lookup and recall lookup to include the resulting aggregate langUnit identity and composition identity when present.
- [ ] Keep a missing-composition fallback for all existing bubbles.
- [ ] Gate: a fixture containing `消息` and `被` as two parts renders as two visual bubbles, while another ordinary `消息` occurrence renders only `消息`.

## Phase 3: Payload Extraction and Provenance

> Trace: rendered composite bubbles become a stable, lossless save payload.

- [ ] Extend `extractSubSegEditorPayload` to read composition and part attributes from each bubble.
- [ ] For an existing composite:
  - preserve its `compositionId`;
  - preserve part IDs and order;
  - rebuild offsets from the current flattened editor text;
  - retain each part's original target type.
- [ ] For ordinary bubbles, emit the existing payload shape unchanged.
- [ ] Ensure text nodes and `<br>` nodes still produce the same normalized newline tokens and flattened `text`.
- [ ] Ensure two bubbles with the same canonical langUnit but different part IDs remain separate content tokens.
- [ ] Add draft comparison support so composition metadata changes count as unsaved changes.
- [ ] Gate: extracting, saving, and extracting again produces an equivalent payload; line breaks remain identical before and after extraction.

## Phase 4: Composite Capture Interaction

> Trace: cycle-target active + selection outside the targeted bubble + Enter.

- [ ] Preserve the existing first branch:
  - selection wholly inside one bubble continues through `captureChinSubstringIntoLinkedSubSeg`;
  - its behavior remains unchanged.
- [ ] Add a distinct composite branch for:
  - active effective cycle target;
  - non-collapsed selection inside the active editor;
  - selection not wholly contained by one bubble;
  - selection that is valid for composite addition.
- [ ] Resolve the active canonical seed and its occurrence scope before mutating DOM.
- [ ] Snapshot the seed instance and remove only that occurrence from the original seed langUnit's instance set; do not delete or reclassify the seed item when other instances remain.
- [ ] Build the ordered aggregate text and target object, then run the same normalized text/type recall-or-new decision used for ordinary capture.
- [ ] Load the recalled aggregate item or create a new aggregate item; attach a composition containing `seedLangUnitId`, the seed part, and the addition part.
- [ ] Rebind the editor tokens from the seed langUnit identity to the resulting aggregate identity, preserving the separate visual part spans.
- [ ] Never create a standalone canonical langUnit for the addition alone.
- [ ] Recompute aggregate text from ordered selected parts and classify:
  - Chinese phrase context -> `chinColl`;
  - English phrase context -> `engColl`;
  - reject or retain current behavior when context is not phrase-like.
- [ ] Preserve the current Enter prevention, caret restoration, target highlighting, and save scheduling behavior.
- [ ] Gate: the exact `消息` + `被` scenario produces two grouped bubbles, one composite occurrence, and no independent `被` canonical item.

## Phase 5: Persistence and Server Rebuild

> Trace: the composite survives POST, canonical rebuild, reload, and a second save.

- [ ] Extend subSeg token normalization to preserve composition and part metadata.
- [ ] Extend langUnit normalization to preserve compositions and normalize their parts.
- [ ] Update instance collection to include:
  - `compositionId`;
  - `partId` where instance-level provenance is required;
  - effective target scope.
- [ ] Update canonicalization keys to use normalized aggregate `text` plus `target.type` for recall/new, while keeping composition provenance out of that canonical key.
- [ ] Keep the original seed item and the resulting aggregate item as separate canonical identities.
- [ ] Update merge behavior so a save removes the matching old seed instance, then upserts the aggregate item/composition and its instance instead of appending duplicates.
- [ ] Update rebuild behavior to remove stale old bindings and stale aggregate parts only from the matching occurrence scope; never remove unrelated seed instances.
- [ ] Keep unrelated occurrences and unrelated compositions untouched.
- [ ] Ensure server writes remain atomic and existing write queues still serialize concurrent saves.
- [ ] Gate: POST -> rebuild -> GET -> reload produces the same composition ID, part IDs, target types, offsets, and linked child identity.

## Phase 6: Linked Cycle SubSeg Integration

- [ ] Ensure a child linked to one composite occurrence is not reused for another occurrence with a different composition.
- [ ] Preserve existing empty-child hydration behavior.
- [ ] Ensure cycling away and back restores the correct effective target and caret offset.
- [ ] Gate: cycle target -> child -> parent -> same composite target round-trip preserves both grouped bubbles and child linkage.

## Phase 7: Classification and Reprocessing

> Trace: aggregate target reprocessing uses the composite context while preserving part classifications.

- [ ] Add explicit aggregate classification input containing:
  - ordered part text;
  - full source context;
  - gaps between parts;
  - context type;
  - part target types.
- [ ] Implement deterministic `chinColl` and `engColl` classification.
- [ ] Make reprocessing order explicit: collect parts -> form aggregate text -> classify aggregate target/context -> remove old seed instance -> recall/create by aggregate text/type -> write the new instance.
- [ ] Define the no-op/rollback rule: if aggregate classification or canonical upsert fails, retain the original seed binding and do not leave a partial aggregate binding.
- [ ] Ensure aggregate reprocessing never overwrites part target types.
- [ ] Ensure an existing inferred target/root operation does not erase composition provenance.
- [ ] Update any worker/inference payloads to distinguish aggregate target text from part text.
- [ ] Define behavior when later edits make parts contiguous, delete an addition, or change language context:
  - recompute aggregate classification;
  - retain provenance unless the part is explicitly removed;
  - collapse back to ordinary behavior only when no additions remain.
- [ ] Gate: classification is stable across repeated rebuilds and does not change ordinary `chinWord`, `chinPhrase`, `engWord`, or `engPhrase` results.

## Completion Criteria

- [ ] `消息` remains a reusable canonical langUnit with its original `chinWord` target.
- [ ] The scoped occurrence containing `消息` plus `被` has one `chinColl` composition with two provenance-preserving parts.
- [ ] No standalone canonical `被` is created by the non-contiguous cycle-target path.
- [ ] Other `消息` occurrences remain unaffected.
- [ ] Composite bubbles render as separate spans with correct individual text.
- [ ] The original seed item remains reusable with its original target type, minus only the reprocessed occurrence binding.
- [ ] The aggregate text/type resolves to one recalled or newly created canonical langUnit with one `chinColl` composition containing two provenance-preserving parts.
- [ ] Other occurrences of the original seed remain unaffected.
- [ ] Cycle navigation, linked child editing, save/reload, inference, deletion, and newline behavior remain functional.
- [ ] Repeated save/rebuild operations are idempotent.
